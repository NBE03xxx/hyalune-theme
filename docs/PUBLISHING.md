# Hyalune：公開用ファイルの管理

公開・開発先は[GitHubのhyalune-theme](https://github.com/NBE03xxx/hyalune-theme)です。利用者向け情報はREADMEと`docs/`へ集約します。開発中の引き継ぎ・操作記録・測定データ・過去の検証画像・環境のバックアップは公開用ソースに含めません。ルートの`AGENTS.md`、`HANDOFF.md`と`outputs/`は開発環境に残すローカル資料です。

## 公開履歴と旧Giteaの保全

GitHubの履歴は、`tools/public-files.txt`で許可したファイルだけを使う初回コミットから開始しています。旧Giteaの開発履歴は、旧リモート、ローカルの保存ブランチ、独立したGit bundleで保全します。既存の開発履歴を書き換えたり、ローカル資料を削除したりしません。

旧履歴には追跡解除済みの開発記録も含まれます。`.gitignore`で過去の履歴は消えないため、保存ブランチ・旧タグをGitHubへ送る全参照pushやmirror pushは使いません。公開用`main`だけを送信します。以後はGitHubの`main`を基準として開発します。

## 公開用ソースの取り出し

履歴やローカル記録を含めない受け渡し用ソースは、次の入口で作成できます。

```sh
python3 tools/export-public.py --output /tmp/hyalune-public-source
```

出力先は**存在しない新規ディレクトリ**を指定します。`tools/public-files.txt`に列挙したファイルだけをコピーし、各ファイルのSHA-256を表示します。`.git`・履歴・remote・ローカル記録・バックアップは含めません。既存ディレクトリへの上書きや、Gitリポジトリの作成・pushは行いません。

公開ファイルを増やす際は許可一覧も更新します。READMEからの文書リンク、紹介画像、導入に必要なコード・生成物と共通入口の保全・復元処理が出力先にそろっていることを確認してください。個人環境のパス・アドレス・認証情報と、Gitコミットに記録される作者メールも点検します。

## 名称と互換性

正式名称はHyalune、リポジトリ名は`hyalune-theme`です。既存checkoutのローカルディレクトリ名は変更せず使えます。Shellの選択名・配置先はHyaluneへ統一しています。GTKの内部配置名、拡張UUID、設定・管理記録は導入・復元との互換性のため維持します。[内部識別名](ARCHITECTURE.md#名称と内部識別名)

## 対応範囲の案内

共通インストーラーは機種固有の指定を要求せず、対応するOS・GNOME・Waylandとユーザー環境を確認します。導入・更新・解除・中断復旧、既存GTK設定・リンクの保全、管理Flatpakの一括解除、旧試用の管理記録移行をVMの専用環境で検証しています。[導入と確認範囲](INSTALL.md)

対象条件、実際に検証した環境、任意ぼかしの制約をREADMEへ残します。対応条件の一致だけで、すべての機器構成の動作確認済みとは案内しません。公開済みリリースと、作業中ソースの実装済み機能を区別します。任意GDMは機種名では制限せず、対応OS・Shell・資源構造と利用者による表示/ログイン/復旧確認を案内します。

## 紹介画像

紹介画像はVM内の独立したGNOMEセッションで撮影します。空の専用ホーム・設定・サンプルフォルダーを使い、通常セッションの個人ファイル・履歴・通知を撮影対象へ出しません。撮影後は目視でユーザー名、ホスト名、パス、アカウント、通知などがないことを確認します。

READMEのDark／Light画像は「Midnight Harbor — 深夜の湾岸都市」を題材とし、海とガラス建築、緑・青の反射光を抽象化した背景で、実際の「ファイル」と「設定」を起動し、Quick Settingsを開いた画面です。Darkを先に大きく掲載し、Lightを続けて比較できる構成にします。両方で同じ背景・アプリ構図と各モードの既定素材を使います。撮影用の背景は画像生成で新規作成し、アプリとQuick Settingsは実画面を撮影します。本テーマ以外のドック・アイコンテーマ・外部ぼかし拡張を装飾目的で追加しません。画像のメタデータにも個人情報を残しません。

紹介画像のアクセントは撮影専用環境のGNOME設定で青緑（teal）を選択しています。テーマ内でQuick Settingsの選択色を固定せず、標準のアクセント設定に追従させます。撮影のために通常の利用環境のアクセントを変更しません。
