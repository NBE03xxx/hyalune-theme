# Hyalune：任意のGDMテーマ

第4層はログイン前のGDM専用です。v0.3.0から機種名・CPU・GPU・仮想化方式による制限を設けず、Ubuntu 26.04／GNOME Shell 50.xと、対応する標準GDM資源の構造で適用可否を判断します。利用者が自身の環境で表示・通常ログインと復旧手順を確認して使う任意機能です。通常の`./install.sh apply`／`remove`／`recover`はGDMを変更しません。

## 設計と変更先

導入先のUbuntu標準GDM資源を読み取り、独自のCSSを加えた専用gresourceをその場で生成します。配布物へUbuntu / GNOMEのCSSやSVGを転載しません。生成した資源には元の著作権・ライセンス表示を保持します。

`/usr/local/share/hyalune/gdm/<SHA256>.gresource`を配置し、`gdm-theme.gresource`のalternativesへ明示選択します。元ファイル、GDMのdconf、PAM、認証設定、自動ログイン、ユーザーのテーマ・拡張は変更しません。初回適用ではデスクトップ壁紙の管理コピーと、ユーザー選択・認証欄の半透明な面を使います。独自の静的SVG背景も明示的に選べます。背景画像の色とUIのアクセント色は別です。通常GDMの入力・ユーザー選択枠は控えめな無彩色を使い、フォーカス時に少し濃くして位置を示します。実ぼかしは加えません。高コントラスト用の資源には、導入先の標準High Contrast CSSを使用します。

所有・復元情報と中断記録はroot専用の`/var/lib/hyalune-gdm/`です。既存候補・選択値・auto/manualを記録し、変更後の差分や資源の改変は競合として停止します。導入・更新・解除・復旧中は専用ロックとdpkg frontendロックを保持します。導入・更新・解除のplanや操作時に、元資源がパッケージ更新等で変わった場合も停止し、古いシステムファイルを無条件に戻しません。

## 既定値とGUIでの編集

GDM管理コンポーネントの版は0.3.1で、外側のガラス面の既定不透明度は32％です。文字・アイコン自体の不透明度は下げず、ユーザー名行・入力欄の背景は透明、選択・フォーカスは白系1pxの枠の濃さで示します。通常14％、ホバー22％、フォーカス28％、押下32％、無効6％です。共通のGTK／ユーザーShellの素材値とは分離しています。VMで描画を検証し、T16で実GDMの表示・ログインを本人確認済みです。

[Hyalune 設定](THEME-MANAGER.md)には、背景画像・不透明度・素材色・ユーザー名色の編集と、通常ユーザーGUIから管理者認証を求める専用窓口を追加しました。既存の固定値と編集中の値、実GDMへの適用は区別します。

## 導入と更新

v0.3.0ではGDM管理も機種名に依存しない条件判定へ移行しました。既存のGDM専用GUI窓口を使う場合は、ソース更新後に`sudo ./install.sh manager-gdm install`で専用窓口も更新します。この更新だけではGDMの外観や背景を変更しません。

VMでは独立したディスク保全、実機では元GDM資源・alternatives・設定の別名保全を用意します。画面が表示されない場合に備え、Ctrl+Alt+F3のテキスト端末から本人のアカウントでログインし、下記の解除・復旧を実行できることを確認してください。導入は対象のデスクトップ利用者がソース内で実行します。

**初回導入も更新も、同じ3コマンドです。**

```sh
sudo ./install.sh gdm plan
sudo ./install.sh gdm set
sudo ./install.sh gdm status
```

`plan`は未導入なら初回導入、導入済みなら更新の予定を表示します。`set`も同じ判定で適用します。初回は現在のデスクトップ壁紙を取り込み、更新では保存済みのGDM背景を維持します。利用者が`apply`と`update`を選ぶ必要はありません。

`status`は配置版・背景の由来・中断・競合を確認します。通常の表示は簡潔な日本語で、自動処理用の詳細は`--json`で取得できます。

導入・更新時はOS・Shell・GDMの読込方式と標準資源、alternatives、所有・元資源のhashを照合します。未対応の構造や外部変更があれば適用前に停止します。通常の操作に`--vm-preview`は不要です。GDM管理だけを別のroot処理へ渡し、通常第1〜3層の導入をsudoで実行しません。

自動ログアウト・GDMサービス再起動・VM再起動は行いません。変更後は作業を保存し、新しいログイン画面で表示を確認します。`status`は既存プロセスの実読み込みを判定しません。

## 初回のデスクトップ壁紙取り込み

ローカルのWaylandデスクトップへログインしている利用者が、前述の`plan` / `set`で初回導入すると、初期背景の既定は`desktop`です。Dark設定なら`picture-uri-dark`、通常配色なら`picture-uri`を取得します。Dark用が空の場合だけ通常用へ戻します。

画像の読み取りとデコードはその利用者の権限で行い、静止画像をPNGへ正規化して専用gresource内へ保存します。GDMは個人HOMEへアクセスせず、元画像の移動・削除やその後の壁紙変更に影響されません。元画像は変更しません。更新は記録した画像を保持し、現在のデスクトップから再取得しません。初回取り込みと常時同期は別です。

`plan`は背景の由来と操作予定を表示し、画像コピーを配置しません。ハッシュ・寸法などの詳細は`--json`で確認できます。元画像のパスは所有記録や通常の出力へ保存しません。`status`で管理背景の由来を確認できます。

GdkPixbufで扱えるローカル静止画像が対象です。PNG・JPEG・静止SVGをVMで確認しています。動的XML・アニメーション・画像なし・読取不能・ローカル以外のURIは、変更前に理由を示して停止します。元画像32MiB、40百万画素、正規化PNG64MiBまでです。画像の表示はGDMの`cover`にそろえ、デスクトップの画像配置・単色合成・複数画面の構図まで再現する機能ではありません。

デスクトップ画像を使わず、従来の独自背景を選ぶ場合は両方へ明示します。

```sh
sudo ./install.sh gdm plan --bundled
sudo ./install.sh gdm set --bundled
```

デスクトップ利用者が分からないroot端末からの初回操作は停止します。管理者が対象を明示する場合は`--desktop-user USER`を使えます。sudo経由なら、その引数もsudo利用者と一致する必要があります。複数人からログインできるGDMの初期背景には、導入を開始した利用者の画像を使います。

壁紙取り込みには既存のPython3 / PyGObject / GdkPixbuf、`runuser`とユーザーのセッションD-Busを使用します。パッケージは自動導入しません。設定・画像の取得は標準HOMEのGNOMEセッションを対象とします。通常の更新は保存背景を維持します。壁紙の取り込み直しは次の専用操作を使います。

## 現在のデスクトップ壁紙へ入れ替える

背景だけを取り込み直す場合は、次の1コマンドです。

```sh
sudo ./install.sh gdm background
```

現在のデスクトップ画像を使うことが既定なので、`--background desktop`は不要です。配置済みGDMの背景と画像URLだけを交換し、不透明度・文字・枠・High Contrast等のスタイルと、元の解除情報を保持します。

事前に予定だけを確認するなら`gdm background --plan`、Hyaluneの背景へ戻すなら`gdm background --bundled`です。更新前の画像・所有記録は保全します。テーマ全体の解除・再適用は不要です。

## 解除と中断復旧

GDMだけを導入前の状態へ戻します。通常のデスクトップテーマは維持します。

```sh
sudo ./install.sh gdm remove
```

元のalternativesの候補・選択とauto/manualへ戻します。表示の切り替えは次のログイン画面で確認してください。自動ログアウトやサービス再起動は行いません。専用の生成資源・保全・処理記録は解除後も保持します。

解除・復旧は機種名の照合を行わず、OS更新後も保存された所有記録・資源・alternativesの整合性を確認して扱います。外部変更は無条件に上書きしません。

操作が中断していた場合は、先に復旧します。

```sh
sudo ./install.sh gdm recover
```

確定前なら変更前へ戻し、確定後なら確定処理を完了します。ログイン画面に入れない場合は、実機のCtrl+Alt+F3のテキスト端末、または準備済みSSH・VMゲストエージェントから実行します。パスワードをスクリプトへ渡す必要はありません。

各操作のコードと資源は`/var/lib/hyalune-gdm/transactions/<ID>/`に保全します。checkoutが使えない場合も、保存されたIDを指定して実行できます。

```sh
sudo python3 /var/lib/hyalune-gdm/transactions/<ID>/manage-gdm.py recover
sudo python3 /var/lib/hyalune-gdm/transactions/<ID>/manage-gdm.py remove
```

通常テーマも解除したい場合は、GDMの解除とは別に、通常ユーザーで`./install.sh remove`を実行します。[通常テーマの解除](INSTALL.md#解除と設定の扱い)

## 確認範囲と利用者による確認

VMの分離領域で管理処理66項目、壁紙の取り込み・保持・差し替え40項目、管理者での共通CLI21項目と環境境界12項目を確認しました。導入・更新・解除、各段階の強制中断・復旧、資源・選択状態の競合、auto/manual復元、元パッケージ変更、symlink競合、未確認実機の拒否を含みます。従来CLIの互換性も別途確認しています。

VMの実GDMで資源の読み込み・標準表示への復元・本人ログインを確認しました。通常ユーザーのテーマと拡張は維持しました。VMの仮想GPUはソフトウェア描画に退避しており、実機GPUの性能測定とは区別します。

T16（Ubuntu 26.04.1 / GNOME Shell 50.1）ではv0.1.0を適用し、解除後の元資源・alternativesの完全復元を照合してから再適用しました。その後、本人が実GDMの表示と通常ログインの成功を確認しました。通常テーマ・拡張・Flatpakの設定と所有記録を維持しています。

専用Shellでユーザー名12状態・入力欄5状態、32％の外側面、文字・アイコンの不透明度維持、High Contrastの標準CSS保持を確認しました。ログイン前のGDMとユーザーセッションのロック画面は別です。ロック画面、多画面、全倍率、全アクセシビリティ条件、再起動の網羅検証は残っています。

[Hyalune 設定](THEME-MANAGER.md)から、背景画像・不透明度・素材色・ユーザー名色を編集できます。専用権限窓口を別途導入し、OS標準の管理者認証を使います。専用窓口・取消・検証・復旧はVMで確認しています。GUIから実際に認証し、次のログイン画面へ反映する本人確認とは区別します。

## 旧コマンドとの互換性

従来の`apply` / `update` / `set-background`と、そのオプションは互換用として受け付けます。新しい手順では初回・更新を`plan` / `set` / `status`、画像の取り込み直しを`background`へ統一しています。通常の利用に`--operation`や`--background desktop`を覚える必要はありません。
