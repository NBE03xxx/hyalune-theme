# Hyalune 設定

「Hyalune 設定」は、通常ユーザーでデスクトップの素材・ぼかし・対応Flatpakを管理するアプリです。GDMは専用の認証・適用操作で扱います。v0.3.0ではDark／LightとUbuntu設定からの自動連動に対応しています。

## 導入・更新・解除

[通常テーマ](INSTALL.md)を導入したソースディレクトリで、通常ユーザーとして実行します。Python3、PyGObject、GTK4、libadwaita、`sassc`が必要です。GTK4 4.22／libadwaita 1.9で動作を確認しています。依存パッケージは自動導入しません。

```sh
./install.sh manager install   # 初回・更新で共通
./install.sh manager status
```

アプリ一覧・検索から「Hyalune 設定」を開きます。初回は配置済みの素材とぼかし選択を確認し、一度適用してから再ログインします。ぼかしoffでも、自動明暗連動に使うHyalune拡張はこの適用で有効にします。更新前に起動していたアプリは、編集を保存して閉じ、開き直してください。起動先は導入済み本体なので、ソースディレクトリを移動しても起動できます。

```sh
./install.sh manager remove   # アプリ本体と起動入口だけを解除
./install.sh manager recover  # アプリ導入・更新・解除の中断を復旧
```

アプリだけを解除しても、テーマ・保存プロファイル・バックアップは残ります。Ubuntu明暗設定への自動連動には導入済みアプリ内の管理処理が必要なため、アプリの解除中は連動も停止します。

## 画面と操作

| 画面 | 使い方 |
| --- | --- |
| 概要 | 配置版、導入状態、競合、中断、反映待ちを確認 |
| 外観 | Dark／Light、共通の不透明度・素材色、プレビュー、部分ごとの調整 |
| ぼかし | Quick Settingsとウィンドウの効果を独立に選択 |
| ログイン画面 | GDMの背景・不透明度・素材色・ユーザー名色を編集し、別操作で適用 |
| Flatpakアプリ | 再検出、対象選択、共通追従・個別設定・現在の適用を保持 |
| 履歴と復元 | 直前の適用へ戻す、中断復旧、通常テーマと管理Flatpakの一括解除 |

外観の初期表示は共通設定が中心です。「部分ごとに調整」を開き、対象を選んだときだけ編集欄を表示します。詳細を閉じても個別値は残り、「この対象を共通設定に戻す」で継承へ戻します。対象はパネル、メニュー・ダイアログ、GTK3ウィンドウ、GTK4ウィンドウです。メニュー・ダイアログの設定は、Hyaluneが調整する面に適用します。

通常のテーマでは、認証・権限確認などの共通システムダイアログと、スクリーンショット操作部などの補助UIはGNOME標準の外観を維持します。ログアウト・電源オフ・再起動の確認はHyaluneの対象です。[適用範囲](ARCHITECTURE.md#外観の適用範囲)

### 編集・保存・適用

1. 値を編集し、画面内のプレビューで確認します。
2. 「変更内容を確認して適用」で変更対象と保留・競合を確認します。
3. 確認後に適用します。既存の所有記録・保全・共有ロックを使います。

「プロファイルを保存」は編集値の保存だけで、デスクトップへ適用しません。「編集を取り消す」は最後の適用値へ編集を戻します。起動・プレビュー・保存・詳細の開閉だけで外観を変更しません。

「Hyaluneの既定値を編集に戻す」は、選択中の明暗の素材とぼかし選択を既定値へ戻します。反対側の素材、Flatpakの設定、GDMは保持し、適用するまでは実環境を変更しません。

| 既定値 | 共通面 | パネル |
| --- | --- | --- |
| Dark | `#1a1a1c / 56%` | `#141416 / 38%` |
| Light | `#f6f6f8 / 78%` | `#f6f6f8 / 74%` |

プレビューはGTK部品の実描画と素材の参考表示です。Shell・GDMの実画面や背景ぼかしを再現するものではありません。対象選択ポップアップは編集値と独立した固定の面を使い、Darkは80％、Lightは94％です。High Contrastでは標準表示を使います。

### Ubuntu設定から明暗を切り替える

このソースのテーマ・Hyalune拡張・管理アプリをそろえると、Ubuntu「設定 → 外観」の変更に自動で追従します。アプリのウィンドウは開いておく必要がありません。Dark／Lightの素材値をそれぞれ保持し、GDMは変更しません。

管理アプリで明暗を選び、明示的に適用する方法も使えます。Ubuntu側の変更で配置状態が変わった場合、未編集の画面は新しい状態へ追従し、未保存の編集は保持します。[自動連動の条件と制約](LIGHT.md)

拡張コード更新後は再ログイン、既存GTKアプリへの初回CSS反映時はアプリの開き直しが必要です。通常の明暗切り替えごとに再ログインする必要はありません。アプリやセッションを自動終了しません。

## Flatpakの追従と個別値

「Flatpakアプリ」で対象を選ぶと、そのアプリの設定を表示します。

| 設定方法 | 適用時の動作 |
| --- | --- |
| 共通設定に追従 | 選択中の明暗と共通素材へ追従 |
| 個別設定 | アプリ専用の素材色・不透明度を保持し、前景・部品の明暗を切り替え |
| 現在の適用を保持 | 既存CSSを維持し、共通外観や自動明暗変更では更新しない |

新しく検出したアプリは対象を選択し、追従または個別設定へ登録して適用します。登録していないアプリを自動連動の対象へ取り込みません。既存CLIで導入したアプリも、政策を選ぶまでは現在の適用を保持します。

起動中・競合・未判定・未対応・未導入は理由を表示します。明示的に選んだアプリが変更できない場合は、全体の適用を始めず停止します。登録済みアプリの暗黙の再反映は保留として扱い、変更できる通常テーマを先に反映する場合があります。自動連動では、起動中で保留したアプリが終了すると再試行します。競合は強制的に上書きしません。

通常テーマと選択Flatpakは同じ処理記録で保全・復旧します。GDMは含めません。LightのGTK3 Flatpakは標準外観を使い、素材値は保存します。[対応範囲とアプリ別解除](FLATPAK.md)

## 履歴と復元

| 操作 | 戻す範囲 |
| --- | --- |
| 直前の適用へ戻す | 直前のプロファイル更新と、その操作に含まれたFlatpakの保存状態 |
| 中断した処理を復旧 | 未確定の変更を逆順で戻す、または確定済み操作の完了処理 |
| テーマを解除して導入前へ戻す | 通常テーマと管理Flatpakの一括復元 |

「直前の適用へ戻す」は、初回導入や拡張コード更新の代用には使えません。外部編集・起動中アプリがある場合も停止します。コードを含む旧版復帰は、その版の互換性を確認した保存済みコード・パッケージと手順を使います。所有記録だけを手でコピーしないでください。

テーマ解除でもアプリ本体・保存プロファイル・保全は残ります。GDMは独立した解除操作です。[通常テーマの解除・復旧](INSTALL.md#解除と設定の扱い)

## GDMの編集と権限窓口

管理者が取得済みの信頼できるソースから、専用処理を別途導入します。通常ユーザー向けアプリの導入とは別で、この操作だけではGDMの外観・背景を変更しません。

```sh
sudo ./install.sh manager-gdm install  # 初回・更新
sudo ./install.sh manager-gdm status
```

「ログイン画面」の「現在のGDM設定を確認」で管理者認証を求めます。編集後の計画と適用にも認証が必要です。取消・認可失敗時に変更を開始しません。GUI全体やcheckoutのPythonをroot起動せず、固定したroot所有の窓口へ限定したJSONを渡します。

背景は保存済みを保持、現在の壁紙、同梱背景、ローカル静止画像から選べます。GUIの初回適用は背景の明示選択が必要です。画像のデコードは通常利用者の権限で行い、元画像32MiB・40百万画素・正規化PNG64MiBまでを扱います。動的XML・アニメーションは停止します。

不透明度・素材色・ユーザー名色をプレビューできます。GDMの既定の面は32％で、ユーザー名の色指定は利用者一覧と認証フォームの名前に限定します。警告・パスワード入力・ボタン・High Contrastは標準の仕組みを維持します。実反映は次のログイン画面で確認し、自動ログアウトやGDM再起動は行いません。[GDMの範囲と復旧](GDM.md)

通常テーマの適用・既定値・解除、Ubuntuの明暗設定ではGDMを変更しません。GDMの編集中データの保存も、実GDMへの適用と別です。

```sh
sudo ./install.sh manager-gdm remove   # 専用窓口だけを解除
sudo ./install.sh manager-gdm recover  # 窓口の導入・更新・解除の中断時
sudo ./install.sh gdm recover          # GDM反映そのものの中断時
```

窓口を外してもGDMの資源・所有記録・保全は残り、GDM用CLIから管理できます。

## 保存先と実装

| 対象 | 保存先 |
| --- | --- |
| アプリ本体 | `~/.local/share/hyalune/settings/app/` |
| 起動入口 | `~/.local/share/applications/io.github.NBE03xxx.Hyalune.Settings.desktop` |
| 通常プロファイル | `~/.config/hyalune/profile.json` |
| GDMの編集内容 | `~/.config/hyalune/gdm.json` |
| アプリ導入の所有記録 | `~/.local/state/hyalune/settings-installer-v1/` |
| 通常テーマ・Flatpakの保全 | `~/.local/state/glass50/`の各管理記録 |
| GDM専用窓口 | `/usr/local/libexec/hyalune-gdm-settings` |
| GDM窓口の導入記録 | `/var/lib/hyalune-gdm-helper/` |
| GDMの所有・復旧記録 | `/var/lib/hyalune-gdm/` |

Python3＋PyGObject＋GTK4／libadwaitaを使用します。GUIとCLIは`tools/manage-settings.py`の版付きJSON APIを共用し、値を検証してSCSSからCSSを生成します。色は`#RRGGBB`、不透明度は0〜1の有限数、ぼかしは真偽値に限定します。任意CSSや実行命令を設定として受け付けません。

プロファイル形式3は明暗別素材を保持し、形式1／2の読取りとhashも維持します。元の所有・復元情報は同じ管理記録へ残します。GDMだけは別の権限・トランザクションを使います。[構成とコード](ARCHITECTURE.md)

通常操作、明暗連動、Flatpak政策、アプリ導入・更新・解除、失敗時の巻戻し・中断復旧をVMで検証しています。GDM GUIの専用窓口・取消・検証・復旧の試験と、本人が実認証して次のログイン画面を確認する工程は区別します。通常GDMの表示・ログイン確認だけで、GUIの実認証も確認済みとはしません。
